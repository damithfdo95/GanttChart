## 1. はじめに

GanttChartが答えるのはたったひとつの質問です。**「テストは期日までに終わるか？」**

QAテスト実行の進捗（総ケース数・完了数・合格数・ステータス別カウント・テスター数・日々のペース）を追跡し、実際のチーム処理能力から**完了予定日を予測**し、リスク状態を可視化するローカルファーストのダッシュボードです。

主な特徴:

- **完全オフライン。** アプリはブラウザ内で完結し、ネットワークリクエストは一切行いません。データはすべて端末内のブラウザデータベースに保存されます。
- **バイリンガル対応。** UIは英語/日本語を即時切り替え。日報はUI言語とは独立にどちらの言語でも生成できます。
- **自動保存。** 変更は自動的に保存されます。ワークスペースに「保存」ボタンはありません。
- **マルチプロジェクト。** ライフサイクル・期日・進捗・処理能力・リスクを一括管理するポートフォリオ画面。
- **復元可能。** JSONバックアップ/復元、ポイントインタイム復元つきのリビジョン履歴、データ整合性の自動保護。

## 2. はじめに（起動方法）

### 動作要件

- **ビルド済みアプリの実行**: 最新のブラウザ（Chrome / Edge / Firefox）。それ以外は不要です。
- **開発・ビルド**: Node.js 18以上（ビルド時にのみ必要。ビルド済みアプリはどのブラウザでも動作します）。

### 開発モード

```powershell
npm install    # 初回のみ。ネットワーク接続が必要です
npm run dev    # 開発サーバーを起動（例: http://localhost:5173）
```

### 本番ビルド

```powershell
npm run build     # 型チェック＋dist/ へバンドル
npm run preview   # ビルド済みアプリをローカル配信（例: http://localhost:4173）
```

`dist/` フォルダが完結した静的サイトです。任意の静的ファイルサーバーで配信できます。注意: `dist/index.html` を `file://` で直接開くことはESモジュールの制約によりブロックされます。`npm run preview` またはローカル静的サーバーをご利用ください。

### 開発者向け

```powershell
npm run test        # Vitest テストスイート（1,200以上のテスト）
```

アプリのアーキテクチャとローカルデータベース設計は [DATABASE.md](DATABASE.md) に記載されています。

## 3. 基本概念

### ナビゲーション

ヘッダーに10画面: **ダッシュボード | 全体 | ガント | 日報 | チケット | 実績分析 | 評価レビュー | RCSメンバー | レポート・エクスポート | 設定**。保存状態インジケーター（✓ ローカル保存済み / … 保存中 / ⚠ 保存失敗）も表示されます。言語切替（EN / 日本語）はダッシュボードのヘッダーにあり、アプリ全体に適用されます。

### 計画と実績

データモデルは2種類に分かれています:

- **計画**（プロジェクト作成時に入力、ガント画面で編集）: 日別の要員配置、勤務時間、残業、目標日。
- **実績**（ダッシュボードで毎日入力）: その日の実際の勤務時間・テスター数・ステータス別カウント（合格 / 不合格 / N/A / SPO対応 / ブロック / リテスト / 質問中）。

累計、ペース、予測、マイルストーンはすべて実行エントリから**自動算出**されます。その日の結果を入力するだけで、すべての計算が更新されます。

### 実行ビューと管理ビュー

ダッシュボードには2つのモードがあります（ヘッダーで切替）:

- **実行** — 日々の実行入力用: ステータス、ライブペース、本日の実行フォーム、タイムライン、What-If。
- **管理** — 分析用: リカバリーシナリオ、計画と実績のギャップ、ブロック/ロスタイム、マイルストーン。

### ライフサイクルステータスと計画ステータス

- **ライフサイクルステータス**はあなたが手動で設定します: 未着手 / 対応中 / 延長 / 保留中 / 完了。進捗100%に達しても自動で「完了」になることはありません。
- **計画ステータス**はスケジュールから自動計算されます: 順調 / リスクあり / キャパシティ不足 / 完了。さらに導出フラグ「期限超過」（期日経過）があります。

### 自動保存

ワークスペースに保存ボタンはありません。変更は入力停止から約0.4秒後に自動保存されます。破壊的操作（削除・リセット・インポート）には必ず確認ダイアログが表示され、その多くは実行前に現在データのバックアップを自動ダウンロードします。

## 4. 画面ガイド

### 4.1 ダッシュボード — 実行ビュー

**アクティブプロジェクト**の作業画面です。以下の内容はすべて、全体/ガントで選択中のプロジェクトを反映します。

**ステータスカード。** 大きな色付きの判定 — 未着手 / 順調 / 進捗先行 / 遅延 / 完了 — と予定完了、期日、バッファ（または遅延）、現在時刻。「このステータスの根拠」を展開すると、実績達成率、QA利用不可時間、予測完了、目標との差分など、判定根拠がすべて表示されます。

**エグゼクティブサマリー。** メトリックカード一式: 総ケース数、完了数、テスト済み（SPO除く）、残り、進捗%、現在/必要テスター数、現在/必要ケース数/時、予定/予測/目標完了、スケジュール差分、実行内訳（合格 / 不合格 / N/A / SPO対応 / ブロック / リテスト / 質問中）。

**ポートフォリオカード。** アクティブプロジェクト、対応中、未着手、延長、保留中、完了、リスクあり — カードをクリックすると全体画面がそのフィルタで開きます。

**入力条件。** 総ケース数、現在のテスター数、開始日、期日、1時間あたりケース数/テスター、日々の残業時間（0〜180分）。すべての計算の元になります。

**処理能力。** 昼休み時間、生産時間/日、チーム処理能力（毎時・毎日）。

**予測。** 必要テスター数、必要時間、予定完了、期日とのバッファ、判定（目標内に完了可能 / 残業が必要）。

**本日の実行フォーム。** 実績の唯一の入力源です:

1. **日付** — 初期値は今日。過去の日も編集できます。**記録された日**ドロップダウンで保存済みの日にジャンプできます。
2. **実際の開始 / 終了 / 実際の残業時間（分） / インターバル取得 / 実際のテスター数。**
3. 入力方法を選択:
   - **累計で入力**（初期設定）— その日の終了時点の累計を入力すると、前日との差分から当日分が算出されます。
   - **当日分で入力** — その日だけのカウントを直接入力します。
4. カウントを入力: 合格、不合格、N/A、SPO対応、ブロック、リテスト、質問中（どのステータスにも当てはまらない残りは「その他」）。
5. **この日を保存** を押します。

保存すると、すべての累計が再計算され、終日のスナップショットが再生成され、現在のテスター数も同期されます。

**ライブステータス / リスク帯。** 実行ステータス、実績レート、予測完了、未完了ステータス（ブロック / リテスト / 質問中のチップ）または「未完了ステータスなし」。

**タイムライン。** 当日のイントラデイタイムライン（開始 / 現在 / 期待値 / 予測 / 目標 / 昼休み）と、計画が複数日にわたる場合の累積マルチデイ進捗チャート（プロジェクト別ドロップダウン付き）。

**テスター数シミュレーション。** テスター数ごとの必要時間と完了予定を示すテーブル。**行をクリックするとそのテスター数が即座に適用されます**。

**エクスポート / インポート / リセット**（ヘッダー）: アクティブプロジェクトのJSONエクスポート、ファイル読み込み、デモデータへのリセット（確認あり）。

### 4.2 ダッシュボード — 管理ビュー

4つの折りたたみ可能な分析パネル（リカバリーと日々の進捗は初期表示で開いています）:

**リカバリー分析。** 実行が遅れているとき: What-Ifシミュレーションで**テスター数**、**実行レート**、**ブロック削減**、**追加生産時間**を調整するか、プリセット（+1テスター、+2テスター、+10%レート、+20%レート、−30分ブロック、バランスの取れた回復）を使用します。シナリオの予測完了、目標/現在/シナリオのチャート、リカバリーギャップ（分・ケース数）、3つのシナリオテーブル、自動生成の「なぜ？」説明が表示されます。**リカバリーオプションを検索**はスケジュールを回復させるシナリオのランキングを生成します。**シナリオを適用**は確認後にテスター数と実行レートのみプロジェクトへ書き込みます（時間とブロック削減はシミュレーション専用）。

**日々の進捗。** 計画と実績の比較: 目標合格率を設定し、日別の実行/合格ギャップと達成率、累積トレンドチャートを確認します。計画行は初期値で**AUTO**。バッジをクリックするとその日は**MANUAL**になり、計画値が再計算後も保持される上書きになります。下の**日々の実行エントリ**テーブル（新しい順・ページング付き）にはすべての保存日が一覧され、**編集**と**削除**ボタンがあります。過去の日を編集すると、以降の累計がすべて再計算されます。

**QAブロック / ロスタイム。** 本日の利用不可時間、実効QA時間、失われた処理能力、利用可能処理能力、テスター稼働率のカード。**ブロックイベントを追加**し、カテゴリ（環境 / ビルド / テストデータ / 要件 / システム障害 / その他）・分数・メモを設定します。カテゴリ別合計がチップで表示されます。

**マイルストーン。** 実行%または合格%のマイルストーンを定義します（初期値は各50/80/100%）。目標に実際に達すると**実績時刻が自動記録**され、差分と未達成 / 到達 / 期限超過のステータスが表示されます。

### 4.3 プロジェクトの作成

**全体**画面で**プロジェクトを追加**を押します。ダイアログは3つのセクションで構成されます:

- **プロジェクト** — 名前（必須）、説明、オーナー、ステータス（予定 / 実行中 / 完了）。
- **テスト計画** — 総ケース数、テスター数、1時間あたりケース数/テスター、目標合格率。
- **スケジュール** — 開始日、目標完了日、日々の残業、毎日の開始/終了時刻、昼休み（12:00–13:00）の有無。

**計算プレビュー**が作成前に処理能力・必要テスター数・必要時間・予定完了・必要日数をライブ表示します。**プロジェクトを作成**を押すと、プロジェクトが保存・アクティブ化され、ダッシュボードへ遷移します。

### 4.4 全体（ポートフォリオ）

「すべてのプロジェクトの状態は？」に答える画面です。

- **9つのサマリーカード**（合計、未着手、対応中、延長、保留中、完了、リスクあり、期限超過、キャパシティ不足）— クリックでテーブルをフィルタ。
- 名前（英/日）やプロジェクトIDで**検索**、ライフサイクル/計画ステータスで**フィルタ**（導出ビュー**要注意**: リスクあり、キャパシティ不足、期限超過、期日7日以内、14日以上更新なし）、列の**並べ替え**。
- **一括操作**: 行を選択して**ステータスを変更**（一括「完了」は完了サマリーつき確認）。
- **行ごとの操作**: ライフサイクルステータス変更（完了は確認あり）、**ガントを開く**で編集へ、エクスポート、削除（確認あり — 削除後のデータ復活はありません）。
- **完了プロジェクト**は任意のステータスで再開でき、完了履歴は保持されます。
- **インポート / 全プロジェクトをエクスポート**: インポートは完全バックアップ・単一プロジェクト・旧形式を自動判別し、それぞれ確認が必要です。

### 4.5 ガント

「各プロジェクトはどのようにスケジュールされ、実行されているか？」に答える画面です。

- **スケジュール概要** — 本物のガントチャート: プロジェクトごとに開始→期日の横棒、進捗フィル、本日のマーカー、ステータス色分け。棒をクリックして選択、ホバーで詳細。
- **プロジェクトセレクター + ステータスフィルタ**（アクティブ / すべて / 未着手 / 対応中 / 延長 / 保留中 / 完了）。
- **日別計画（編集）**: 日ごとの予定/欠席テスター、行ごとの開始/終了/残業/インターバル上書き、非稼働日フラグ、メモ。**翌日を追加**は営業日のみ作成します（週末と日本の祝日は自動スキップ）。
- **日別処理能力**: 毎日/累積処理能力、日ごとの残りケース、予測完了（ハイライト）、不足/追加必要日数、推奨テスター数、目標との差分。
- **プロジェクトリスト**: 折りたたみ式のプロジェクトヘッダーと、読み取り専用の日別予測テーブル。

### 4.6 日報

SPO形式の日報（と朝の報告）を生成します。ヘッダーの**日付**選択と**報告書の言語**（English / 日本語 — UI言語と独立）、**日報 / 朝の報告**のモード切替があります。

**ライフサイクル**: 日付を開くと下書きが自動作成されます。**確定**は不変のスナップショットを凍結します（確定済みの報告書は再計算されません）。確定済み報告書の**編集（改訂版を作成）**は、元の報告書を保持したまま新版の下書きを作成します。**報告書履歴**テーブル（ページング付き）にすべての下書き/確定/改訂版が**表示**ボタン付きで一覧されます。

**日報のセクション:**

- **出席状況** — 欠勤のみ記録します（記録のないメンバーは出席扱い）。行ごとに: メンバー（RCSメンバー選択または自由入力）、ステータス（欠勤 / 有給休暇 / 半日休 / 遅刻 / その他）、勤務開始/終了、休暇種別、コメント。チーム別出席サマリーは自動計算されます。
- **本日のアクティビティ** — ライブQA計画から自動シードされ、自由に編集できます。各行は**⟳ 実行エントリからコピー**で当日のカウントを取り込め、並べ替えもできます。これらは報告書ローカルのコピーであり、編集しても計画データには影響しません。
- **進捗報告** — アクティビティから計算された読み取り専用の進捗行。
- **本日のトピック** — 自由記述（タイトル＋説明）、並べ替え可。
- **翌営業日** — 自動サジェスト（残作業、キャパシティリスク、予定従事者）＋手動追加。営業日のみ。
- **JIRA URL** — 報告書レベル。空欄なら設定のプロジェクトJIRA URLにフォールバック。
- **プレビュー**: **生成**、**データを更新**（自動コンテンツを再シード、手動編集は保持。確認あり）、**下書きを保存**、**確定**（確認あり）、**下書きを削除**。プレビュー文言は編集可能。その後**クリップボードにコピー / TXTエクスポート / PDFエクスポート / Excelエクスポート**。

**朝の報告モード**: **本日のスケジュール**セクション（自動シード＋サジェスト）、専用プレビュー、同じエクスポートボタンを備えています。

### 4.7 チケット

アクティブプロジェクトのバグチケット管理です。

- サマリーカード: 合計、今月、未対応、Critical/Major、クローズ、報告者数。
- **チケット追加/編集**: JIRAチケットキー、タイトル、JIRA URL、作成日、報告者（RCSメンバーまたは外部）、重要度（Critical / Major / Minor / Trivial）、ステータス（オープン / 対応中 / 解決済み / クローズ / 却下 / 重複）、メモ。キー/URLの重複は警告されます。
- チケットテーブル（新しい順・ページング付き）には**JIRAで開く**リンク、報告者の本人特定ヒント、編集/削除があります。

### 4.8 実績分析

スーパーバイザー向けのテスター別実行分析です。

- **期間セレクター**（月 / 上期 / 下期 / 年 / カスタム範囲）とプロジェクト範囲。サマリーカード（テスター数、テスト済みケース数、発見バグ数、稼働日数、プロジェクト数）。
- **テスター実績テーブル**: テスターごとのケース数、平均/日、合格/不合格/ブロック/リテスト、バグ、実行ソース（自動 / アシスト / 手動 / 手動修正）。**詳細を表示**でメトリックカード、バグ発見率、プロジェクト別内訳、月次トレンドチャートが開きます。
- **テスター実行帰属 — 日次実行**: プロジェクト用フォームと同じ形式でテスターの日次数値を入力・修正できます。整合性チェックのチップは、テスター記録とプロジェクトの日次実行エントリが一致しない日付を警告します。記録テーブル（ページング付き）は編集/削除に対応します。
- **テスター実績の同期**: **変更をプレビュー** → **現在のプロジェクトを同期**または全プロジェクト同期（確認あり）。手動入力は「手動修正」になり、同期で上書きされません。
- **テスター割り当て**: アクティブプロジェクトにテスターごとの割り当て期間（開始/終了日）を追加。アクティブ/非アクティブ切替、削除。
- **アシスト割り当て**: 実行日ごとに、出席を考慮したサジェストが各メンバーの数値を事前配分します。すべてのセルが編集可能で、過剰配分や重複はライブ検証されます。編集した行は**手動修正**タグ付き。
- **出席チェック**: 欠勤なのにケースが記録されている日を警告します。

### 4.9 評価レビュー

スーパーバイザーによる定期テスター評価のワークフローです:

1. **期間**と**テスター**を選択。
2. **客観的メトリック**を確認: プロジェクト数、稼働日数、ケース数、平均/日、バグ数、バグ発見率、ステータス別内訳、プロジェクト別貢献。
3. **前期間 → 現期間**の比較テーブルでメトリックごとの差分を確認。
4. **スーパーバイザーレビューメモ**を記入: ステータス（下書き / 完了）、サマリー、強み、改善点、メモ — そして**レビューを保存**。
5. **レビュー履歴**に過去のレビューが一覧されます。**この期間を読み込む**でセレクターがその期間に切り替わります。削除には確認があり、客観データには影響しません。

客観データは参考情報であり、評価や賞与の決定はスーパーバイザーに委ねられます。

### 4.10 RCSメンバー

すべての記録の背後にあるメンバーマスター（安定した本人情報）です:

- **メンバーテーブル**: ID（自動採番、例: USER0009）、名前、役割、開始/終了日、在籍/不在籍ステータス、**名前履歴**。名前を変更しても過去の記録は壊れません — 過去の名前は同じ安定IDに解決されます。
- **メンバー追加/編集** — 名前履歴エディタ付き（重複と日付順を検証）。
- **本人特定センター**（要注意のレガシー記録があるときのみ表示）: 未一致または曖昧な名前を確認し、個別または一括でメンバーに解決します。曖昧な記録が自動解決されることはありません。データ品質パネルが問題を種類別に集計します。

### 4.11 レポート・エクスポート

- **フィルター**: 日付範囲と出席ステータス（報告書ベースのデータセットに適用）。
- **データエクスポート**: 15種類のデータセット（プロジェクト、出席状況、日報、日々の進捗、実行ログ、実行履歴、バグチケット、テスター実績、テスター日次詳細、テスター評価、RCSメンバー、テスター割り当て、WBS/計画、テスター処理能力、残業）— 各**CSV / XLSX / JSON**。
- **ワークブック全体をエクスポート（XLSX）**: 全データセットを1つのマルチシートブックに（ヘッダー固定、オートフィルター、日付/パーセント書式）。
- **管理レポート**（XLSX / PDF）: プロジェクトごとに1行 — 期日、残りケース、現在/必要テスター数、処理能力ギャップ、予測完了、必要残業、リスクステータス。
- **バックアップと復元**: **バックアップをエクスポート**はワークスペース全体（両方のストレージ）を1つのJSONファイルに書き出します。**バックアップをインポート**は確認後に、**現在データのバックアップを自動ダウンロードしてから**、ワークスペースをファイル内容で置き換えます。

### 4.12 設定

- **スーパーバイザー名**（報告書の作成者/確定者として使用）と**プロジェクトJIRA URL**（日報のフォールバック）。
- **追加休暇日**: 1行に1つの `YYYY-MM-DD`。翌営業日のサジェストに使用されます（週末と日本の祝日は常に自動除外）。
- **進捗計算ルール**: 作業%と完了%の分母を選択。
- **報告テンプレート**: 日報の英/日テンプレートを編集（プレースホルダー: `{active_test_names}` `{attendance}` `{activities}` `{topics}` `{progress}` `{jira_url}` `{next_business_day}`）。いつでもデフォルトに戻せます。
- **危険な操作**: ストレージ診断（モード、リビジョン、整合性、スナップショット、最終保存）、**バックアップをダウンロード**、**すべてのローカルデータを削除**（確認＋事前バックアップ自動ダウンロード。全データ削除後、初期プロジェクトを再シード）。

### 4.13 リビジョン履歴

（設定画面内。）ワークスペースの変更はすべて、理由（編集、インポート、リカバリー、プロジェクト作成/削除、報告書確定など）と変更サマリー付きの番号付きリビジョンとして記録されます。

- 行をクリックすると、何が変わったかの**読み取り専用プレビュー**が表示されます。
- **リビジョン #n を復元**は確認後、その時点の状態を持つ**新しい**リビジョンを作成します。何も削除されません — 新しい履歴はすべて保持されます。
- **履歴バックアップをエクスポート**は保持されているジャーナルと現在の状態をダウンロードします。
- 直近50リビジョンがローカル保持され、整合性はカードで表示されます（検証済み / 警告 / 履歴利用不可）。

## 5. アプリ全体の機能

- **言語切替** — ダッシュボードヘッダーの `EN | 日本語`。画面をまたいで保持されます。報告書の言語は日報画面で独立に選択します。
- **自動保存と保存状態** — ナビゲーション横のインジケーターが常時 ✓ ローカル保存済み / … 保存中 / ⚠ 保存失敗 を表示します。
- **ページング** — 長いテーブル（実行エントリ、報告書履歴、チケット、リビジョン履歴、テスター記録、割り当てなど）は10行/ページでページングされます。1ページに収まる場合、ページャーは表示されません。
- **確認ダイアログ** — 破壊的操作には必ず確認があります。インポート/復元/クリア操作は実行前に現在データのバックアップを追加でダウンロードします。
- **オフライン** — ネットワークアダプター無効でも動作します。外部リンクは入力したJIRA URL（新規タブで開く）のみです。

## 6. データの安全

**データの所在。** あなたのブラウザのローカルデータベース（IndexedDB、データベース名 `GanttChartDB`）に保存され、フォールバックとして旧localStorageコピーが保持されます。サーバーへの送信は一切ありません — サーバー自体が存在しないためです。

**バックアップ。** **レポート・エクスポート → バックアップをエクスポート**（または設定 → バックアップをダウンロード）を定期的に実行してください — ワークスペース全体を含むポータブルなJSONファイルが1つ作成されます。どのマシン/ブラウザでも**バックアップをインポート**で復元できます。バックアップは**ブラウザやマシン間の移行**にも使います。

**復元可能な状態。** アプリはリビジョンジャーナル（直近50リビジョン）とリカバリースナップショットを維持しており、誤編集は**設定 → リビジョン履歴**からロールバックできます。

**データの消去。** 設定 → 危険な操作 → **すべてのローカルデータを削除**は、確認後にすべてのGanttChartキーとブラウザデータベースを削除します。事前にバックアップが自動ダウンロードされます。ブラウザ自身の設定からブラウザデータを消去しても同じ結果になりますが、安全なバックアップは作られません — 必ず先にエクスポートしてください。

## 7. トラブルシューティング

注意が必要なとき、アプリは上部に平易なバナーを表示します:

| バナー | 意味 | 対処 |
|---|---|---|
| **「ローカルブラウザストレージで保存しています」** | ブラウザデータベースを利用できないため（例: プライベートモード）、ローカルストレージに保存しています。 | 操作はそのまま続行できます。プライベートモードを終了/ブラウザ再起動でデータベースに戻ります。 |
| **「復旧が必要です」** | ブラウザデータベースが失われ、保持されていたローカルコピーに最新の変更が含まれていない可能性があります。利用可能な最良のデータとして開かれています。 | データを確認してください。最近の変更が欠けている場合は、最新のバックアップファイルをインポートしてください（レポート・エクスポート → バックアップをインポート）。 |
| **「データベース移行が完了していません」（理由付き）** | ローカルストレージからブラウザデータベースへの一回限りの移行が失敗しました。データは保持されており、次回起動時に再試行されます。 | 通常は自動的に解決します。繰り返す場合はバックアップをエクスポートし、アプリのタブをすべて閉じてから、ブラウザ開発者ツール → Application → IndexedDB の `GanttChartDB` を削除し、再読み込みしてください。必要ならバックアップをインポートします。 |
| **「ローカルデータの読み込みに失敗しました」** | 保存データの一部が読み取れず、安全な初期状態で起動しました。 | 元データは保護されています — **破損データを書き出す**を実行し、最新のバックアップファイルから復元してください。 |
| **⚠ 保存失敗**（インジケーター） | 保存を書き込めませんでした。 | ディスク容量/ブラウザの保存上限を確認してください。アプリ内の状態は使用可能なままなので、このうちにバックアップをエクスポートしてください。 |
| ブラウザ/マシン切替後にデータがない | ブラウザストレージはブラウザ・マシンごとに分かれています。 | バックアップファイルでデータを移動してください（データの安全を参照）。 |

鉄則: **バックアップファイルを定期的に保存してください** — ブラウザの状態に関係なく、どこでも機能します。

## 8. 知っていると便利な機能

1. **What-Ifの行はクリックできます** — テスター数の行をクリックすると即座に適用されます。
2. **「このステータスの根拠」** — ステータスカード下の展開パネルに計算根拠がすべて表示されます。
3. **AUTO/MANUALの計画バッジ** — バッジをクリックすると、その日の計画値が再計算後も保持される上書きになります。
4. **報告書の言語 ≠ UIの言語** — 英語UIで日本語の報告書も生成できます。
5. **⟳ 実行エントリからコピー** — 日報のアクティビティ行ごとに当日のカノニカルなカウントを取り込みます。
6. **記録された日ドロップダウン** — 本日の実行で、保存済みの任意の日にジャンプして編集できます。
7. **マイルストーンの自動記録** — 目標達成時に実績時刻が自動で記録されます。
8. **リカバリーオプションを検索** — 遅延時に回復シナリオのランキングを生成するトグルです。
9. **完了プロジェクトは削除されません** — アクティブから非表示になり、再開可能です。確定済み報告書の参照も保護されます。
10. **PDFエクスポート**はブラウザの印刷ウィンドウを開きます — サイトのポップアップを許可してください。
11. **管理ビューは別世界** — 実行/管理トグルの奥にあるリカバリー/日々の進捗/ブロック/マイルストーンのパネルを見落とさないでください。
12. **リビジョン復元は非破壊** — 常に新しいリビジョンを作成するため、また戻ることもできます。

## 9. よくある質問

**Q. データはどこかに送信されますか？**
いいえ。アプリはネットワークリクエストを一切行いません。すべてのデータはブラウザ内に残ります。

**Q. 複数人で同じデータを共有できますか？**
直接はできません — データはブラウザごとです。バックアップ（JSON）ファイルを交換するか、報告用にデータセット（CSV/XLSX/JSON）をエクスポートして共有してください。

**Q. ブラウザのデータを消去するとどうなりますか？**
アプリのローカルデータはすべて削除されます。先にバックアップをエクスポートしてください（レポート・エクスポート → バックアップをエクスポート）。

**Q. UIが英語ですが、日本語の報告書が必要です。**
日報 → 報告書の言語セレクター — UI言語とは独立に選択できます。

**Q. ケース数では順調なのに、なぜ「キャパシティ不足」になるのですか？**
計画エンジンは合計だけでなく、1日ごとの必要処理能力と利用可能処理能力を比較します。ガント画面の日別処理能力テーブルを確認してください。

**Q. 確定した報告書の誤字を直したいです。**
その日付を開き、**編集（改訂版を作成）**を選択してください。元の報告書は不変のまま、改訂版が優先されます。

**Q. アプリを別のマシンへ移すには？**
プロジェクトフォルダをコピー（または `dist/` を配信）し、データはバックアップファイルで移動してください。

**Q. オフラインで動きますか？**
はい。計算、報告書、エクスポートを含め完全に動作します。

**Q. SPOとは何ですか？**
[用語集](#10-用語集)を参照してください。SPO対応は合格/不合格フロー外で処理されたケースです。

**Q. 変更を元に戻せますか？**
はい — 設定 → リビジョン履歴で、最近のリビジョンをプレビューして復元できます（新しいリビジョンが作成され、何も削除されません）。

**Q. 週末や祝日を手動で設定する必要はありますか？**
いいえ。週末と日本の祝日（振替休日を含む）はすべての場所で自動的に除外されます。会社独自の休暇は設定で追加できます。

**Q. 保存インジケーターが「保存失敗」です。**
トラブルシューティングを参照 — 保存容量を確保し、アプリが使用可能なうちにバックアップをエクスポートしてください。
